## Open (follow-ups)

- **AIS**: verify the aisstream.io and MarineTraffic clients against the live services with a real key (both written from the public docs); MarineTraffic history request for trip periods.
- **Europe-wide routing build**: run with `Routing:Region` = −32…45 / 27…72; the build is tile-wise with bounded memory (see decisions), only time (hours) and PostGIS disk are needed. Untested at that scale so far.
- **13 legacy import** (needs the old SQL Server database).
- **14 canals, rest**: opening times of movable bridges (today a flat waiting penalty, see decisions); fairway areas are used as channel-preference zones, not yet as centreline sources (see decisions).
- Europe PBF import (2026-10-18): done on the dev box in 54 min after the two scan passes – 542,778 sea marks, 7,516 new harbours (6,592 updated), 2,077,788 POIs. Earlier runs died with the host crash and two column overflows (`Seamark.Sectors` → 4000, `Poi.Kind` → 200); the import is batch-tolerant and resumable since then. Waterways/bridges/no-go areas and buoy-chain fairways are derived region-wide from Overpass in chunks (see the rows above); lakes only where imported (`import-water`).
- Depth areas: the z12 Seascape import covers the whole routing region (146,704 areas, 8 min with 8 parallel fetches). Values come in fathom steps (1.83 / 3.66 / 5.49 / 9.14 / 18.29 m), drying areas as −16. No inland depths (lakes are routed without draft limits).
- Lean Europe base map (`tools/build-basemap.sh lean europe`): on hold until the WSL memory cap is set (the Planetiler run and the import together crashed the host once).
- **Area routing, next steps**: Europe-scale run of the visibility build (not tiled; nodes and edges for the whole region are held in memory), narrow natural channels closed by the 150 m coast buffer and without a buoy chain (lower `Routing:CoastBufferM` or add a passage), per-area cost tuning (coast penalty no longer exists in area mode).
- Routing region is 4.5–19.5 E / 52–60 N (Dutch coast to the Stockholm archipelago, IJsselmeer included); a wider region is a config change plus a rebuild.

## External services (all behind an interface, swap by registration)

## Decisions made during implementation

| Topic | Decision |
|-------|----------|
| Project layout | `Sms.Application` folded into `Sms.Api` (endpoint groups + `Access`/`Viewer` services); `Sms.Routing*`, `Sms.Worker` deferred until routing/tracking exist |
| Authorization | One scoped `Access` service + a `Viewer` record that yields EF-translatable visibility predicates instead of policy/resource handlers — same matrix, less plumbing |
| CSRF | Cookie auth + `SameSite=Lax` + mandatory `X-Requested-With: XMLHttpRequest` header on state-changing `/api` calls (SPA interceptor) instead of ASP.NET antiforgery tokens |
| Rich text | Plain textarea → paragraphs; server-side `HtmlSanitizer`, Angular `[innerHTML]` sanitising. A real editor (TinyMCE/Quill) can be dropped in later |
| Geography | Columns are `geography(Point,4326)`; coordinates are projected in memory because PostGIS has no `ST_X/ST_Y` for geography |
| Images | ImageSharp **3.1.12** (Six Labors Split License) — 4.x requires a paid license for Release builds. The open advisories against 3.1 concern TIFF/BigTIFF, HistogramEqualization and ICC CLUT parsing; decoding is restricted to JPEG/PNG/WebP and uploads are limited to signed-in crew, so only the ICC parsing one is reachable (memory DoS by a crafted profile). Revisit when buying a 4.x license |
| Mail | `System.Net.Mail.SmtpClient` to Mailpit; switch to MailKit for a real provider |
| SigNoz | Pinned `signoz/signoz:v0.116.1` + collector `v0.144.2` (last upstream docker-compose before Foundry); a `signoz-setup` container registers the admin org on first start because the collector replaces its pipelines with `nop` until an org exists |
| Angular | 21 (Node 22.14 on the dev machine is below Angular 22's minimum) |
| Calendar tokens | Data-protection-encrypted ids instead of stored secrets |
| Routing build | In-process background job (admin button) instead of a separate `Sms.Routing.Builder` CLI; same tables as spec 10 §10.2 so a CLI can be split out later |
| PDF | `SimplePdf` (≈100 lines, PDF 1.4, standard Helvetica, WinAnsi) writes the cost statement – no PDF library and no font files to ship; switch to PDFsharp/QuestPDF if images or non-Latin text are needed |
| Robustness | Every route is exercised by `EndpointSmokeTests`; binding/validation must answer 4xx. Found and fixed: null e-mail in auth endpoints (ArgumentNullException from Identity), JSON bodies on multipart upload endpoints (`ReadFormAsync` throws), geography X/Y projected in SQL (privacy zones) |
| Tile-wise graph build | Land polygons stream from the shapefile straight into `routing_land`; the region is then processed in tiles of `Routing:TileCells`² start cells (`WaterGraphTiler`): each tile loads only its clipped land from PostGIS, builds the quadtree, writes nodes/edges via COPY and stitches to already built neighbours through their retained border cells. Cells fully covered by land are pruned at the top instead of descending to the minimum size. One longitude scale per region (cells widen towards the north); the new version only becomes active at the end |
| Track segments | Rebuilt per trip after a 20 s debounce (in-process); no separate worker |
| Maps | Leaflet replaced by MapLibre GL 6. Base style from OpenFreeMap (vector, OpenMapTiles schema); the MapLibre worker is served as a static asset (`/maplibre-gl-worker.mjs`) because Vite's dependency pre-bundling breaks its relative worker URL |
| Sea marks | Stored as `geometry(Point,3857)` with the raw OSM tags (jsonb) and the few attributes the style needs; tiles cut in SQL (`ST_AsMVT`) by a separate minimal-API project so the tile server can scale/cache independently of the API |
| Tenancy | Resolved per request from `Host`/`X-Forwarded-Host` against `ShipDomains`; no separate Angular build — the SPA asks `/api/site` on start and switches routes (`canMatch`) |
| Passage cost | `PassageCostFactor` is 1.0: a discount made routes ride cheap OSM fairway lines to their ends (Kiel → Heiligenhafen 38.2 instead of 35.9 nm). Channel preference (penalty on open water next to buoyed fairways) steers instead. Point snapping prefers grid nodes over passage vertices (`routing_meta.grid_nodes`), otherwise a click next to a fairway line routed to the line's end |
| Weather | Observations are recorded by the ingest endpoints (OsmAnd/OwnTracks/points), not by a background job: the fix is the trigger, and the 1 nm / 15 min debounce is checked against the ship's last observation in the DB. The forecast is cached per 0.05° cell for 15 minutes so a harbour panel, a context-menu request and live tracking near the same spot cost one Open-Meteo call. Xweather tiles are proxied (10-minute memory buckets) because the URL carries the secret |
| Area routing (`Routing:Mode=areas`, default) | The user's design: open bodies of water are routed by visibility, narrow waters by precomputed lines. Build: land is buffered by `CoastBufferM` (150 m), unioned and simplified (`SimplifyM`); nodes = convex corners of that coast (the only points a shortest path bends at), a `LatticeM` (20 km) lattice on the open sea kept `LatticeClearM` from land, anchors for every harbour and passage end (moved to the buffer boundary when they lie inside it), and corners of charted banks ≤ `ShallowNodeDepthM`; edges = each node's `VisibleNeighbours` (24) nearest nodes within `MaxVisibilityM` (40 km) whose straight line does not cross land (may run along a headland). Passages (canals, fairways, buoy chains), bridges, locks, channel preference and depth limits work exactly as before on top. Query: a click snaps to the nearest node it can see, harbours to their anchor; A* and string pulling unchanged. Nodes sit 1 m outside the buffered coast, so a leg along a straight stretch of coast touches nothing and any leg into land is a plain intersection (the relate-based Crosses/Contains test missed segments with both ends on the boundary; a safety net drops any leg that crosses the raw land and reports it). Bridges, locks and opening bridges price visibility legs within `BridgeMatchAreaM` (1.5 km) of their point, and the string pulling treats too-low bridges (that circle) and too-shallow areas as land, otherwise it straightened a detour back through the Fehmarnsund. Western Baltic region: 12.1 k area nodes / 172 k visibility edges (plus 22 k passage nodes) instead of 108 k / 311 k grid, build ≈ 3 min; Kiel → Heiligenhafen 33.4 sm (grid: 36.2 sm), Kiel Bight → Lübeck Bight 44.3 sm in 3 legs, 52.6 sm north of Fehmarn with 30 m air draft. The quadtree stays available as `Mode=grid` |
| Channel following | Measured with a scratch script (share of route length within 400 m of a derived buoy chain) on the user's cases Bagenkop → Marstal → Svendborg and the Marina Wendtorf entrance. Three things were wrong: the failed Europe import had wiped every derived fairway (re-derived: 65 chains in the region), the channel penalty looked only at an edge's midpoint (meaningless for a 20 km visibility leg; now priced by the length the leg spends in the 1.5 km band around a buoy chain, charted fairway areas excluded), and routes without a ship context were computed for a draft of 0 (now `Routing:DefaultDraftM` = 1.5 m, so charted shallows below 2 m are avoided by default and the buoyed channel through them is the only way). The harbour approach (`HarbourAccessM`) is exempt from the depth limit, otherwise harbours in charted-shallow basins were unreachable. Bridges are stored with their OSM way geometry: a leg gets the clearance wherever it crosses the line (Great Belt: east bridge 65 m, west bridge 18 m) |
| Resumable PBF import | The two scan passes over europe-latest (≈ 40 min) are the expensive part; their result (the matched elements as Overpass-style JSON) and the index of the next batch are written next to the PBF (`<file>.<flags>.<size>-<mtime>.elements.json` / `.progress.json`). A rerun with the same file and flags skips the scans and continues with the batch that was not written yet; the upfront replacement of derived corrections only runs on a fresh start. The files are deleted after a successful run. Together with the batch tolerance (a batch failing on one bad element is skipped and counted) a Europe run no longer has to start over |
| No-go areas (Sperrgebiete) | OSM `seamark:type=restricted_area` whose restriction forbids entry (no_entry, entry_prohibited, no_boating …) and every `military_area` are imported by the waterway import (Overpass and PBF) as derived `Block` corrections ("Sperrgebiet Eckernförde-Süd (no_entry)", bathing zones with motorboat=no). Blocks count as land in the graph build, so no leg crosses them. Areas whose entry is restricted at times (restricted_entry, entry_restricted, to_be_avoided – the Todendorf/Putlos firing ranges, "Warngebiet …") become `Avoid` corrections: edges inside cost ×3 by the length inside (`Routing:AvoidPenaltyFactor`), so a route crosses one only when the detour is long. Both kinds show in the corrections editor (red / amber) and can be deactivated. Areas with other restrictions (no anchoring, no fishing) are untouched |
| Bridges with charted spans | OSM has a long bridge (Great Belt, Fehmarnsund, Øresund) as a way with one clearance and its navigation spans as `seamark:type=bridge` nodes with their own clearance (Østbroen 65 m, Vestbroen 18 m × 70 m wide). `Obstacles.WithSpans` replaces such a line by the windows (± 500 m) around the span points within 250 m of it – the span's clearance – and the remainder with clearance 0: edges crossing the remainder are dropped from the graph, the span points become visibility anchors so legs run through them, and the smoother keeps the impassable parts as obstacles for every ship (the low spans for ships above their clearance). The audit reports a leg crossing a bridge outside its span ("bridge"). Lines without charted spans keep their single clearance |
| Inland water bodies | The coastline-based land polygons count every lake as land (IJsselmeer, Markermeer, Randmeren, Mälaren, Schweriner See). `POST /api/admin/routing/import-water?bbox=` fetches `natural=water` lakes/reservoirs/lagoons (ways with a perimeter above 3 km, all multipolygon relations) from Overpass, stitches the member ways into rings with islands as holes, keeps areas ≥ 0.5 km² as derived `Water` corrections, and the graph build subtracts them from the land tiles they touch. Region extended south to 52 N for the IJsselmeer and the Randmeren (Zeewolde). Not yet in the PBF import (relations need assembling there) |
| Chunked waterway import | The replacement of derived corrections is bounded by the queried bbox (`import-waterways?bbox=`), not by the envelope of the parsed ways: a river fetched by one 2° chunk stretched that envelope over the neighbouring chunks and deleted their passages and Sperrgebiete again. Region-wide runs therefore go chunk by chunk without losses; the Seascape depth import fetches 8 tiles at a time (whole region ≈ 8 min instead of hours) |
| Routing audit | `POST /api/admin/routing/audit?sample=150&maxNm=40&neighbours=3[&draft=]` routes every sampled harbour to its nearest neighbours and checks each route: no leg over land or through a Block beyond the harbour approach, no leg through water charted below draft + margin unless on a passage, and where a buoy chain ends within 2 km of the destination the last 4 km must run ≥ 50 % inside it. The report lists counts per check and findings with a position; the user's sample cases (Marstal, Svendborg, Wendtorf) are instances of these rules, the audit finds the rest systematically |
| Routing, how it works | Build (`RoutingGraphBuilder`, minutes): OSM land polygons → adaptive quadtree over water (cells 20 km offshore down to 150 m at the coast) → nodes/edges in pgRouting tables, coast edges cost ×1.2, water near derived fairways and fairway areas ×1.5, canals/fairways/buoy chains as passage edges with bridge clearance, lock and opening-bridge costs, depth areas as `min_depth_m`; harbours linked to their nearest water node. Query (`SeaRouter`, ms): snap both ends (harbour access node or nearest node within a cell), pgRouting A* over the active version restricted to a bounding box and to edges open for the ship's draft/air draft, then string pulling against the land polygons; harbour pairs are cached per graph version |
| Open Waters | Evaluated 2026-10-17: `tiles.openwaters.io/seamap` (vector seamarks + Seascape depths, CC-BY, z0–14, weekly planet PMTiles) could replace our own sea-mark tiles; kept ours for now because the import also feeds routing (fairways, bridges, locks) and harbours, and OSM freshness is under our control.
